# Деплой на своём железе

Архитектура: всё крутится в Docker Compose на вашей машине, ничего в облаке
арендовать не нужно. Бот получает обновления через long polling — публичный
адрес ему не нужен. Единственное, чему нужен публичный HTTPS-адрес — Mini App
(таково требование самого Telegram: клиент грузит Mini App по `https://`
напрямую, локальный сервер не подходит). Это закрывается постоянным Cloudflare
Tunnel — без покупки VPS, но с одним ручным шагом, который нельзя сделать
автоматически (вход в аккаунт Cloudflare через браузер).

Дашборд учителя тоже пробрасывается через тот же туннель — отдельным Public
Hostname на тот же tunnel token, поэтому второй `cloudflared`-контейнер не
нужен. Порт `8080` на самой машине (LAN/localhost) при этом остаётся —
удобно для доступа без интернета. Раз дашборд становится публичным, его
защищает только логин/пароль сотрудника (как и раньше) — этого достаточно
для типового случая, но если хочется второй слой, в Cloudflare Zero Trust
можно включить **Access** на этом Public Hostname (email-код или Google-вход
перед тем, как запрос вообще попадёт на дашборд) — необязательно, добавляется
в любой момент позже без изменений в коде.

## 1. Разовая настройка Cloudflare Tunnel

Это единственный шаг, который нужно сделать руками — требует входа в браузере.

Домен проекта: **biolog.com.uz** (регистратор ahost.uz).

1. Зарегистрируйте (если ещё нет) бесплатный аккаунт на https://dash.cloudflare.com
2. **Add a site** → `biolog.com.uz` → план **Free**. Cloudflare выдаст два
   своих nameserver'а вида `xxx.ns.cloudflare.com`.
3. В панели ahost.uz замените текущие NS домена на выданные Cloudflare.
   Сейчас домен делегирован на четыре сервера ahost'а:
   ```
   dns1.ahost.uz   dns2.ahost.uz   ns1.ahost.cloud   ns2.ahost.cloud
   ```
   Их нужно убрать и оставить только две записи Cloudflare. Делегирование в
   зоне `.com.uz` обновляется от 15 минут до нескольких часов; пока Cloudflare
   не покажет статус **Active**, туннель работать не будет.
4. В боковом меню откройте **Zero Trust → Networks → Tunnels → Create a
   tunnel** → тип **Cloudflared** → дайте имя, например `course-platform`.
5. На шаге установки коннектора выберите **Docker** — Cloudflare покажет
   команду вида `cloudflared tunnel run --token eyJhbG...`. Скопируйте именно
   токен (всё после `--token`).
6. На шаге **Public Hostname** укажите `app.biolog.com.uz` → Service:
   `HTTP` → `miniapp:80`.
7. Добавьте второй Public Hostname тому же туннелю (Zero Trust → Networks →
   Tunnels → ваш туннель → **Public Hostname → Add a public hostname**):
   `admin.biolog.com.uz` → Service: `HTTP` → `dashboard:80`.
7a. Добавьте третий Public Hostname тем же способом — публичная страница
   проекта на голом домене: `biolog.com.uz` → Service: `HTTP` →
   `landing:80`. Отдельно стоит добавить и `www.biolog.com.uz` на тот же
   сервис, иначе набранный с `www` адрес не откроется.
8. Вставьте токен в `.env` в корне проекта:
   ```
   CLOUDFLARE_TUNNEL_TOKEN=eyJhbG...
   ```

HTTPS-сертификаты на оба поддомена Cloudflare выпускает сам — ни Let's
Encrypt, ни открытые порты на роутере не нужны (машина за NAT, входящих
соединений не принимает: туннель сам открывает исходящее соединение наружу).
Universal SSL выпускается не мгновенно: после активации зоны это заняло ~25
минут, по документации Cloudflare — до 24 часов. Пока сертификата нет,
HTTPS отдаёт обрыв соединения, хотя HTTP уже работает. Проверить состояние:
`./check-ssl.sh` в корне проекта либо **SSL/TLS → Edge Certificates** в
панели (статус должен стать **Active**).

Оба Caddyfile редиректят HTTP → HTTPS по заголовку `X-Forwarded-Proto` от
границы Cloudflare — иначе набранный руками `http://admin...` открывал бы
панель по незашифрованному соединению, и пароль сотрудника ушёл бы открытым
текстом.

## 2. Переменные окружения

```bash
cp .env.example .env                                    # TELEGRAM_API_ID/HASH + токен туннеля
cp apps/api/.env.production.example apps/api/.env.production
```

Заполните `apps/api/.env.production`: `JWT_SECRET` (любая длинная случайная
строка), `OWNER_TELEGRAM_ID`, `TELEGRAM_BOT_TOKEN`. Остальное уже настроено
на адреса внутри docker-сети.

**Пароль базы данных.** В корневом `.env` задайте `POSTGRES_PASSWORD` —
сильное случайное значение (`openssl rand -base64 24`). Тот же пароль должен
стоять внутри `DATABASE_URL` в `apps/api/.env.production` (замените `CHANGE_ME`).
Без `POSTGRES_PASSWORD` контейнер postgres просто не стартует — это специально,
чтобы не уехать в прод с дефолтным паролем.

## 3. Сборка и запуск

Первый запуск:

```bash
docker compose -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.prod.yml exec api npx tsx src/db/migrate.ts
```

**Обновление кода в дальнейшем — одной командой:**

```bash
./scripts/deploy.sh
```

`deploy.sh` пересобирает и поднимает контейнеры, дожидается готовности БД и
**сам накатывает миграции** — чтобы не выйти в прод с новым кодом на старой
схеме (это самый лёгкий шаг для «забыл»). При интерактивном деплое ошибка
миграции — фатальна: скрипт остановится и покажет её, а не оставит гадать.
(На автозапуске после перезагрузки миграции по-прежнему накатывает
`start-stack.sh`, но там их провал сайт не роняет — см. §5.)

## 4. Проверка

- Страница проекта: `http://localhost:8282` (LAN) или `https://biolog.com.uz`
- Дашборд: `http://localhost:8080` (LAN) или `https://admin.biolog.com.uz`
  (публично, через туннель) — оба ведут в один и тот же контейнер
- API напрямую наружу не торчит — проверяется через дашборд/miniapp
- Mini App: откройте `https://app.biolog.com.uz` в браузере — должна
  открыться (авторизация через Telegram initData сработает только изнутри
  самого Telegram, это ожидаемо)
- Кнопка Mini App в боте ставится через Bot API, без BotFather:
  ```bash
  curl -s -X POST "https://api.telegram.org/bot<ТОКЕН>/setChatMenuButton" \
    -H 'Content-Type: application/json' \
    -d '{"menu_button":{"type":"web_app","text":"Открыть",
         "web_app":{"url":"https://app.biolog.com.uz/"}}}'
  ```
  В отличие от временного Quick Tunnel, этот адрес постоянный — повторять
  после каждого перезапуска больше не нужно.
- Откройте бота в Telegram, нажмите на кнопку Mini App — должна открыться и
  работать.

## 5. Автозапуск после перезагрузки

Стек поднимается сам при загрузке машины — настраивать ничего не нужно,
всё уже включено.

Работают два независимых механизма:

1. **`restart: unless-stopped`** у всех контейнеров — Docker сам поднимает их,
   когда стартует его демон. Покрывает обычную перезагрузку.
2. **systemd-юнит `course-platform.service`** — запускает
   `scripts/start-stack.sh`, который делает `compose up -d` и накатывает
   миграции. Покрывает то, чего не умеет пункт 1: стек был снят через
   `compose down`, изменился `docker-compose.prod.yml`, или вместе с
   обновлением кода приехала новая миграция.

Полезные команды:

```bash
systemctl status course-platform         # что со стеком
sudo systemctl restart course-platform   # поднять/перезапустить
sudo systemctl stop course-platform      # остановить (тома целы)
sudo journalctl -u course-platform -n 50 # лог последнего запуска
```

**Важно:** для ручного подъёма нужен именно `restart`, а не `start`. Юнит
объявлен как `Type=oneshot` с `RemainAfterExit=yes` — после первого запуска
systemd считает его активным, и `start` тихо ничего не делает, даже если
контейнеров уже нет. На саму загрузку это не влияет, там юнит стартует с нуля.

Миграции при загрузке применяются, но их провал **не роняет сайт**: стек уже
поднят и обслуживает запросы, а в журнале останется `WARNING: migrations
failed`. Проверить стоит через `journalctl`.

Отдельная оговорка про ноутбук: закрытие крышки по умолчанию усыпляет машину,
и сайт уходит в офлайн до пробуждения. Простой в неактивности отключён
(`sleep-inactive-ac-type = nothing`), а вот крышка — нет. Если машина работает
как сервер, поведение крышки нужно поменять в `/etc/systemd/logind.conf`
(`HandleLidSwitch=ignore`).

## Резервные копии базы данных

Все данные (ученики, оценки, история, банк заданий) живут в одном
docker-томе `postgres_data` на этой машине. Отказ диска или случайный
`docker volume rm` без бэкапа = потеря всего. Поэтому — ночной дамп с
ротацией.

**Скрипт.** `scripts/backup-db.sh` снимает `pg_dump` из контейнера, жмёт в
gzip, при желании шифрует и удаляет копии старше `BACKUP_RETENTION_DAYS`
(по умолчанию 14). Дампы пишутся в `backups/` (в `.gitignore` — там
персональные данные, в репозиторий им нельзя).

Разовая проверка вручную:

```bash
./scripts/backup-db.sh
ls -lh backups/
```

**Автоматический запуск (cron, каждую ночь в 03:00):**

```bash
crontab -e
# добавить строку (путь подставьте свой):
0 3 * * * cd "/home/umariko/Desktop/my project" && ./scripts/backup-db.sh >> backups/backup.log 2>&1
```

**Шифрование (рекомендуется, если копия уедет с машины).** Задайте
`BACKUP_GPG_PASSPHRASE` — дамп будет зашифрован AES256, файл получит
расширение `.gpg`. Пароль храните ОТДЕЛЬНО от бэкапов (иначе шифрование
бессмысленно).

**Копия вне машины.** Локальный дамп спасает от «сломалась БД», но не от
«сгорела машина». После бэкапа синхронизируйте `backups/` куда-то наружу —
второй диск, NAS или объектное хранилище (`rclone`/`rsync`).

**Восстановление.** `scripts/restore-db.sh` разворачивает дамп (операция
ПЕРЕЗАПИСЫВАЕТ базу):

```bash
./scripts/restore-db.sh backups/course_platform_2026-08-28_03-00-00.sql.gz
docker compose -f docker-compose.prod.yml restart api
```

**Проверьте восстановление хотя бы один раз** на тестовой базе (поменяйте
`DB_NAME` в скрипте) — бэкап, который ни разу не разворачивали, бэкапом не
считается.

## 6. Сертификатный экзамен (Milliy Sertifikat)

Отдельная вкладка «Сертификат» в панели и в Mini App. Структура варианта
жёстко задана государственной спецификацией (`docs/Biologiya-MS2025.pdf`) и
описана одним модулем — `apps/api/src/lib/certExam.ts`:

| Задания | Тип | Как отвечает ученик | Баллы |
|---|---|---|---|
| 1–32 | закрытые | выбор A–D в Mini App | по 1, автопроверка |
| 33–35 | закрытые, общее условие | выбор A–F | по 1, автопроверка |
| 36–40 | открытые, краткий ответ | фото решения через бота | по 1, ставит учитель |
| 41–43 | письменная работа | фото решения через бота | 30 / 35 / 10, ставит учитель |

Итого 115 баллов.

Порядок работы учителя:

1. «Сертификат» → выбрать курс, задать название и дедлайн → **Создать**.
2. **Прикрепить файл через бота** — открывается чат с ботом, туда шлётся
   PDF варианта (можно и фото).
3. **Ключ ответов 1–35** — сетка из 35 селектов; у 33–35 доступны E и F.
4. **Опубликовать**. Кнопка неактивна, пока нет файла или ключ неполон —
   это же проверяется и на сервере (409), а не только в интерфейсе.

Ученик открывает вкладку, нажимает «Прислать файл варианта в чат» — бот
отправляет вариант ему в личный чат (скачивание прямо в приложении не
работает: WebView Telegram блокирует blob-ссылки, а файл защищён токеном,
поэтому обычной ссылкой его не отдать). Дальше ученик отмечает ответы 1–35
(сохраняются автоматически), по заданиям 36–43 отправляет фото решения
через бота — **отдельно для каждого задания**, затем сдаёт работу.
Момент сдачи фиксирует `is_late` и замораживает вердикт по каждому
закрытому заданию: последующая правка ключа не переписывает уже сданные
работы.

Учитель видит работу в «Ждут проверки», ставит баллы за 36–43 (больше
максимума поставить нельзя) и пишет комментарий. Только после этого
ученику становятся видны его баллы и правильные ответы — до проверки они
скрыты, иначе ключ вычислялся бы повторными попытками.

**Оценивание.** Спецификация предписывает для 1–40 модель Раша (IRT); она
требует статистики по большой выборке сдающих и для одного класса
недостоверна, поэтому здесь применяется прозрачная схема «1 балл за верный
ответ». Веса 41–43 (30/35/10) взяты из спецификации без изменений — они
абсолютные, а не выборочные.

## 7. Банк заданий

Задание — самостоятельная сущность, а не «позиция N в варианте M». Вариант
стал списком ссылок на задания (`cert_items` + `cert_exam_items`), поэтому
статистика ответов копится **на вопрос** и переживает правку или удаление
варианта.

Тема проставляется автоматически: спецификация жёстко привязывает разделы
к номерам заданий (1 — биология как наука, 2–11 — клетка и генетика,
12 — систематика, 13–19 — растения и животные, 20–23 — человек,
24–28 — вид и популяция, 29–32 — экосистема, 33–35 — логика,
36–43 — общебиологические задачи). Маппинг живёт в `lib/certExam.ts`.

Вкладка «Банк заданий» в панели показывает по каждому вопросу: тему, ключ,
число ответов, долю верных, в скольких вариантах использован. Фильтр
«Проблемные» оставляет только то, что требует внимания.

**Детектор опечатки в ключе.** Ключ вводится 35 буквами руками, и одна
опечатка молча засчитывает вопрос неверно всем ученикам. Если большинство
(≥50% при ≥8 ответах) выбрало не тот вариант, что стоит в ключе, задание
подсвечивается предупреждением с подсказкой, какую букву выбирают на самом
деле. Ключ правится прямо в банке — исправление действует на все будущие
сдачи, но **не переписывает уже проверенные работы**: вердикт по каждому
заданию заморожен в момент сдачи.

**Поле «Источник»** (необязательное) — например `Spectrum 2026, вариант 1,
№5`. Если в новом варианте указать тот же источник, система поймёт, что это
тот же вопрос, и продолжит копить его статистику вместо того, чтобы завести
дубликат. Без источника вопросы считаются разными — всё работает, просто
статистика не объединяется.

### Якорные задания

Калибровка задаёт шкалу **внутри одного варианта** (начало отсчёта — средняя
сложность его заданий), поэтому способности, измеренные на двух несвязанных
вариантах, несопоставимы: рост ученика неотличим от того, что второй вариант
оказался легче. Связывают шкалы **якори** — задания, повторённые из прошлого
варианта, чья сложность уже известна.

Обходной путь «связать через одних и тех же учеников» не работает: он требует
допущения, что способность между сдачами не изменилась, — а это ровно то, что
мы измеряем.

Рекомендуемое число — **8** (около 20% от 40 оцениваемых заданий). Якори
должны покрывать весь диапазон трудности, а не быть восемью лёгкими.

В панели: на карточке варианта — счётчик якорей; в редакторе ключа кнопка
«Подобрать якори» показывает задания прошлых вариантов этого курса с долей
верных и числом ответов, «Взять» переносит и ключ, и источник. Перед
публикацией с числом якорей меньше 8 выводится предупреждение — именно
предупреждение, а не запрет: полностью новый вариант это осознанный выбор,
просто его нельзя будет сравнить с остальными.

Зачем это нужно помимо текущей пользы: калибровка сложности заданий
(модель Раша из спецификации) требует порядка 30–100 ответов **на каждое
задание**. Пока у задания нет своей личности, накопленные ответы для
калибровки непригодны — поэтому банк введён заранее, чтобы данные начали
копиться с сегодняшнего дня.

### Карточка задания

Клик по номеру или теме в банке открывает карточку — всё, что система знает
о вопросе:

**Паспорт.** Код вида `2-0002` (номер задания + внутренний id), номер, тема,
ключ, тип по спецификации (Y1/Y2/O1/O2 — выводится из позиции), источник,
кто завёл в систему, статус.

**Заполняется вручную:** текст задания (необязательно — вариант и так лежит
файлом; заполненный текст делает банк самостоятельным и пригодным для
поиска), автор задания (обычно авторы сборника, а не тот, кто вводил),
когнитивный уровень I/II из §VI спецификации, заметки.

**Статистика.** Ответов, доля верных, различающая способность, сколько
оставили без ответа. Плюс главное — **разбор по каждому варианту ответа**:
сколько процентов выбрали, и отдельно сколько сильных и сколько слабых.
Голое «45% верных» говорит, что задание трудное; разбор по вариантам
объясняет почему — и часто показывает, что ключ стоит не на той букве.

**История использования** — в каких вариантах задание встречалось и какую
долю верных дало в каждом. Резкий скачок между сдачами обычно значит, что
группа выросла, — либо что вариант утёк.

**Флаги.** Похоже на опечатку в ключе · слабые решают чаще сильных ·
слишком лёгкое · слишком трудное · есть вариант, который никто не выбирает ·
ключ правили после появления ответов.

Два последних стоит пояснить. **Мёртвый дистрактор** — вариант, который
выбирают меньше 5%: задание фактически становится выбором из трёх, и шанс
угадать растёт с 25% до 33%. **Правка ключа задним числом** помечается
отдельно, потому что статистика до и после правки посчитана по разным
определениям «верного» и складывать их нельзя.

**Вывод из оборота** вместо удаления: задание перестаёт предлагаться в
якори, но история ответов сохраняется — иначе прошлые результаты молча
изменились бы.

## Если домен появится и захочется webhook вместо polling

Не обязательно, но если понадобится: поставьте `BOT_UPDATES_MODE=webhook` в
`apps/api/.env.production`, перезапустите `api`, затем:

```bash
docker compose -f docker-compose.prod.yml exec api \
  npm run set-webhook --workspace=apps/api -- https://admin.biolog.com.uz/telegram/webhook
```
