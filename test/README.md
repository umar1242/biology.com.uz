# Смоук-тесты API

Два скрипта, которые прогоняют боевой API целиком — не моки, а живые
HTTP-запросы к запущенному серверу.

```bash
npm run test:api        # оба набора
npm run test:api:staff  # только учительская часть
npm run test:api:student # только ученическая часть
```

Требуется: запущенные `docker compose up -d` (postgres + telegram-bot-api) и
`npm run dev:api`. Учителя `alice` / `bob` и помощник `helper_carol` должны
существовать с паролем `secret1234`.

## Что покрыто

**`e2e-staff.sh`** (97 проверок) — вход и оба вида отказа, курсы, модули,
уроки (live/recorded + валидация несовместимых полей), ДЗ, ученики, выдача и
отзыв доступа, штрафные баллы и блокировка, помощники и их права по курсам,
сводка дашборда, очередь проверки, настройки, удаление в правильном порядке.

**`e2e-student.sh`** (32 проверки) — вход по Telegram initData (включая
подделанную подпись), выдача своего курса, ДЗ и сдач, и — главное —
изоляция: посторонний ученик получает 404 на каждом ресурсе, а
заблокированный или отозванный доступ убирает курс из выдачи.

Скрипты создают свои данные и не трогают чужие, но пишут в ту же базу —
гоняйте их на dev-базе, а не на боевой.

## Как читать результат

Каждая строка — `ok` или `FAIL` с ожидаемым и фактическим HTTP-кодом; в конце
сводка `N passed, M failed` и список падений. Оба набора должны давать
`0 failed` — любое падение это регрессия.

Ученический набор сам создаёт себе курс/модуль/урок/ДЗ и выдаёт доступ, а по
выходе удаляет всё созданное, поэтому не зависит от того, что лежит в базе, и
не копит мусор между прогонами.
