# 07. Сертификатный экзамен

Платформа проводит пробные экзамены по структуре Milliy Sertifikat. Источник —
государственная спецификация, `docs/Biologiya-MS2025.pdf`.

## Структура варианта

43 задания, четыре группы:

| Номера | Тип | Что это | Как проверяется |
|---|---|---|---|
| 1 — 32 | Y1 | закрытые, варианты A–D | автоматически по ключу |
| 33 — 35 | Y2 | закрытые, варианты A–F, общий текст на три задания | автоматически по ключу |
| 36 — 40 | O1 | краткий ответ | фотография, руками |
| 41 — 43 | O2 | развёрнутое решение | фотография, руками |

Веса развёрнутых заданий взяты из спецификации: 30, 35 и 10 баллов.
Регламент времени — 100 минут на первую часть и 80 на вторую.

Структура зашита в `lib/certExam.ts` как чистые функции: номер задания
определяет его тип, набор вариантов ответа и максимум баллов. Проверяется
модульными тестами.

## Жизненный цикл варианта

```
черновик ──▶ прикреплён файл ──▶ введён ключ 1–35 ──▶ опубликован
```

Опубликовать вариант без файла или с неполным ключом нельзя: API отвечает
`409`. Пока вариант не опубликован, ученик его не видит.

Файл варианта преподаватель присылает боту (PDF или фотография). Запоминается
не только идентификатор файла, но и его вид: идентификаторы Телеграма
привязаны к типу, и фотографию нельзя отправить обратно как документ.

## Как сдаёт ученик

Закрытые задания решаются в приложении. По заданиям 36–43 ученик присылает
фотографии решения через бота.

При отправке на проверку закрытая половина проверяется сразу, и вердикт по
каждому заданию **замораживается на строке ответа**. Более поздняя правка ключа
не перепишет уже сданную работу.

Баллы ученику не показываются до проверки преподавателем. Это не про вежливость:
если возвращать результат сразу, пересдачами можно вычислить весь ключ.

## Итоговый балл

Формула сверена с настоящим сертификатом, а не восстановлена по описанию.

Две половины весят поровну. Тестовая половина — 40 заданий, письменная — 75
баллов. Каждая приводится к шкале в 65 баллов, затем берётся среднее:

```
тестовая  = верных / 40 × 65
письменная = баллов / 75 × 65
итог      = (тестовая + письменная) / 2
процент   = min(итог / 65, 1) × 100
```

Процент выше 65 баллов не растёт — меняется только уровень:

| Балл | Уровень |
|---|---|
| > 70 | A+ |
| 65 — 69,9 | A |
| 60 — 64,9 | B+ |
| 55 — 59,9 | B |
| 50 — 54,9 | C+ |
| 46 — 49,9 | C |
| ниже 46 | сертификат не выдаётся |

Задания 36–40 при этом относятся к **тестовой** половине, а не к письменной:
так считает настоящий сертификат.

До этой правки платформа складывала все баллы в один итог из 115, из-за чего
письменная часть весила 65 процентов вместо половины.

Оценка помечена как приближённая: A+ по ней недостижим, потому что платформа
не применяет модель Раша к оценке ученика (см. [08](08-модель-раша.md)).

## Банк заданий

Задание живёт отдельно от варианта. Один и тот же вопрос, поставленный в двух
вариантах, — это одна карточка в банке с общей статистикой.

Что показывается по каждому заданию:

- **Доля верных ответов.** Слишком лёгкое или слишком трудное задание видно сразу.
- **Индекс дискриминации по Келли.** Сравниваются верхние и нижние 27 процентов
  по баллу. Показывается только начиная с 30 попыток: ниже это шум в одежде числа.
- **Мёртвые варианты ответа.** Те, которые выбирает меньше 5 процентов.
- **Якорные задания.** Рекомендуется восемь на вариант — они связывают варианты
  между собой.

Ограничение классического подхода: дискриминация считается **внутри одного
варианта**, потому что ранжирует учеников по баллу за этот же вариант. Сравнить
трудность задания из первого варианта с заданием из второго нечем. Ради этого и
существует модель Раша.
