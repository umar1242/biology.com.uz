# Технологический стек

Выбор — на усмотрение агента (зафиксировано в grilling-сессии). Критерии:
соло-разработка силами агента, VPS-бюджет ~$10-20/мес, масштаб 1-5 учителей /
50-200 пользователей — минимум движущихся частей важнее теоретической
масштабируемости.

## Бэкенд

| Слой | Выбор | Почему |
|---|---|---|
| Язык/рантайм | **TypeScript / Node.js 20 LTS** | Один язык для бэкенда и обоих фронтендов (дашборд + Mini App) — меньше контекста для агента, общие типы между слоями. |
| Web-фреймворк | **Fastify** | Легче и быстрее Express, нативная интеграция с Zod через `fastify-type-provider-zod`, минимум магии. |
| Валидация | **Zod** | Схемы валидации = TS-типы автоматически, не дублируем вручную. |
| ORM/миграции | **Drizzle ORM + drizzle-kit** | SQL-подобный API, не мешает уже написанным `CHECK`-constraint'ам и enum'ам в `db/schema.sql` (в отличие от Prisma, где кастомные constraint'ы — боль). Наш `schema.sql` становится первой миграцией как есть. |
| БД | **PostgreSQL 16** | Уже выбрана при проектировании схемы. |
| Telegram-бот | **grammY** | TS-first, современная альтернатива node-telegram-bot-api/Telegraf, активно поддерживается. |
| Приём больших файлов | **Локальный Bot API сервер** (официальный `telegram-bot-api`, бинарник на Go) | Снимает лимит 50 МБ у обычного Bot API — решено ранее при проектировании идеи. |
| Аутентификация | **JWT (`jose`)** + **argon2** для паролей | Без Redis/сессионного хранилища — меньше инфраструктуры при таком масштабе. |
| Фоновые задачи | **node-cron**, тем же процессом | Только два периодических job'а (штрафные баллы за несданное ДЗ, напоминания об истечении доступа) — отдельная очередь (BullMQ и т.п.) избыточна. |

## Фронтенд

| Приложение | Выбор | Почему |
|---|---|---|
| Дашборд учителя | **React + Vite + TypeScript**, TanStack Query, Tailwind | Классическая SPA-админка с sidebar, не нужен SSR. |
| Telegram Mini App | **React + Vite + TypeScript**, `@telegram-apps/sdk`, TanStack Query | Тот же стек, что и дашборд — переиспользование паттернов/компонентов; SDK для initData и нативных фич Mini App. |

## Инфраструктура

- **Один VPS** (Ubuntu 24.04), всё через **Docker Compose**: `postgres`,
  `telegram-bot-api` (локальный сервер), `api` (Fastify), плюс сборки
  дашборда и Mini App как статика.
- **Caddy** как reverse proxy — автоматический HTTPS без ручной возни с
  certbot (обязателен и для Telegram-вебхука, и для Mini App — оба требуют
  валидный HTTPS).
- Отдельного CI/CD не заводим на старте — соло-разработка, деплой скриптом
  (`git pull && docker compose up -d --build`). Можно добавить позже, если
  понадобится.
- Менеджер пакетов монорепозитория — **npm workspaces** (не pnpm: в этом
  окружении нет прав на глобальный симлинк для corepack/pnpm, а npm ≥7
  справляется с workspaces без внешних зависимостей).

## Структура репозитория

```
apps/
  api/         — Fastify-бэкенд: REST API, Telegram-вебхук, cron
  dashboard/   — веб-дашборд учителя/помощника (Vite + React)
  miniapp/     — Telegram Mini App ученика (Vite + React)
db/
  schema.sql   — источник истины по структуре БД (уже написан)
docs/          — проектные документы (этот файл, api-design.md)
docker-compose.yml
```
