# 02. Архитектура

## Из чего собрана платформа

Семь контейнеров в одном `docker-compose.prod.yml`, на собственном железе за
NAT. Входящих соединений машина не принимает вовсе.

| Сервис | Что делает | Порт наружу |
|---|---|---|
| `postgres` | PostgreSQL 16, единственное хранилище | нет |
| `api` | Fastify, бот, задачи по расписанию | нет |
| `telegram-bot-api` | локальный сервер Bot API | нет |
| `dashboard` | Caddy со статикой панели | `127.0.0.1:8080` |
| `miniapp` | Caddy со статикой мини-аппа | `127.0.0.1:8181` |
| `landing` | Caddy со статикой витрины | `127.0.0.1:8282` |
| `cloudflared` | туннель наружу | нет |

Порты трёх фронтендов открыты только на локальный адрес: до них добираются
либо из локальной сети, либо через туннель по внутренней сети Docker.

## Почему туннель, а не проброс портов

Машина стоит за NAT. Cloudflare Tunnel открывает исходящее соединение сам, и
входящие порты на роутере не нужны. Он же выпускает сертификаты: ни Let's
Encrypt, ни открытого 443 порта на маршрутизаторе.

Маршруты туннеля настраиваются в панели Cloudflare Zero Trust, а не в
репозитории — `cloudflared` с токеном читает их удалённо. Три публичных имени:

```
app.biolog.com.uz    → miniapp:80
admin.biolog.com.uz  → dashboard:80
biolog.com.uz        → landing:80   (и www.biolog.com.uz туда же)
```

## Путь запроса

```
браузер / Телеграм
      │
      ▼
Cloudflare (TLS, кэш статики)
      │
      ▼
cloudflared ──внутренняя сеть Docker──▶ Caddy (dashboard | miniapp | landing)
                                             │
                                    /api/v1/* │ reverse_proxy
                                             ▼
                                          api:3000
                                             │
                                             ▼
                                        postgres:5432
```

Caddy панели и мини-аппа проксируют `/api/v1/*` на `api:3000`, поэтому для
браузера фронтенд и API лежат на одном origin и междоменных запросов в
рабочем окружении не возникает. Витрина API не проксирует: там нечего
запрашивать.

## Почему локальный сервер Bot API

Обычный Bot API отдаёт файлы не больше 50 МБ. Видео уроков крупнее. Локальный
сервер снимает лимит и, в режиме `TELEGRAM_LOCAL=1`, вместо ссылки на скачивание
возвращает абсолютный путь на своей файловой системе.

Из-за этого том с файлами примонтирован в `api` только на чтение, а контейнер
добавлен в группу `101`: сервер Bot API пишет файлы с правами `0640` от этого
владельца, и без членства в группе примонтированный том оказался бы нечитаемым.
Так фотографии домашних работ читаются прямо с диска, минуя облачную загрузку.

## Приложение

Один процесс Node 20 совмещает три роли:

**HTTP API.** Fastify, префикс `/api/v1`, 17 наборов маршрутов. Разделены на
две группы: `/api/v1/...` для персонала и `/api/v1/app/...` для учеников.

**Бот.** grammY. По умолчанию длинные опросы (`BOT_UPDATES_MODE=polling`) —
публичный адрес для них не нужен. Режим вебхука доступен и используется, когда
адрес есть.

**Задачи по расписанию.** node-cron внутри того же процесса:

| Задача | Расписание | Что делает |
|---|---|---|
| `missed-homework-sweep` | каждые 15 мин | штрафной балл за просроченное ДЗ, автоблокировка на пороге |
| `access-expiry-sweep` | каждый час | предупреждение об истечении доступа и напоминания после |
| `homework-deadline-reminder` | каждые 30 мин | напоминание ученику о дедлайне |
| `live-lesson-reminder` | каждые 5 мин | напоминание о живом уроке |
| `unreviewed-homework-digest` | ежедневно в 9:00 | сводка непроверенных работ преподавателю |
| `trial-expiry-sweep` | каждый час в :10 | заморозка доступа после пробных уроков |

У всех задач `noOverlap`: медленный проход не даёт запуститься второму по тем
же строкам. При остановке процесса планировщики гасятся до закрытия пула
соединений, иначе задача успела бы выстрелить в закрывающуюся базу.

## Мягкая остановка

Docker шлёт `SIGTERM` при каждом перезапуске и передеплое. Порядок остановки
важен и задан явно: сначала перестаём принимать новую работу (задачи и бот),
потом даём Fastify дожать текущие запросы, и только последним закрываем пул
Postgres. На всё десять секунд, после чего процесс выходит с ненулевым кодом,
чтобы сбой был виден, а не растворился в SIGKILL от Docker.

## Границы, которые стоит знать

Одна база и один процесс приложения. Горизонтального масштабирования нет и не
планировалось: задачи по расписанию живут в процессе и во втором экземпляре
пошли бы дважды.

Хранилище файлов — Телеграм. Платформа хранит не байты, а `file_id`.
Собственного объектного хранилища нет.

Часовой пояс расписаний фиксирован смещением `+05:00`: в Узбекистане нет
перехода на летнее время, и хранить правила часовых поясов не за чем.
