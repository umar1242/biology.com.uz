# 09. Безопасность

Документ описывает, что защищено, как именно и где границы. Порядок — от
входа в систему к данным и дальше к эксплуатации.

## Модель угроз

Что мы считаем ценным:

1. **Персональные данные несовершеннолетних.** ФИО, телефон ученика, телефон
   родителей, фотографии тетрадей. Это самое чувствительное в системе.
2. **Изоляция между преподавателями.** Один преподаватель не должен видеть
   учеников и материалы другого.
3. **Ключи сертификатных вариантов.** Утечка ключа обесценивает экзамен.
4. **Учётные записи персонала.** Доступ к панели даёт доступ ко всему выше.

От кого защищаемся: посторонний из интернета; ученик, который хочет увидеть
чужие работы или ключ; отчисленный ученик, который хочет вернуться; помощник,
которому дали не все права.

Чего в модели нет: злонамеренный преподаватель внутри своего арендатора и
злонамеренный владелец платформы. Против них технических барьеров нет.

## Аутентификация

### Персонал

Логин и пароль. Пароль хранится хешем **argon2** (`@node-rs/argon2`), в чистом
виде нигде не появляется. Сессия — JWT на **12 часов**, подписанный HS256.

Вход ограничен по частоте отдельно от остального API: **8 попыток за 5 минут**
с адреса. Перебор пароля через API нецелесообразен.

Самозаписи преподавателей нет. Учётную запись создаёт владелец платформы
командой бота, а владельца определяет числовой Telegram ID из переменной
окружения `OWNER_TELEGRAM_ID`. Никакого «забыли пароль» по почте тоже нет, и
это осознанно: почтовый канал в системе отсутствует, а восстановление через
него было бы самой слабой дверью.

### Ученик

Отдельного пароля у ученика нет. Личность подтверждает Телеграм через
**initData** — подписанный пакет, который мини-апп присылает при открытии.

Проверка (`lib/../telegram/initData.ts`) делает три вещи:

1. Считает HMAC-SHA256 по каноничной строке данных с ключом, производным от
   токена бота, ровно по документации Телеграма.
2. Сравнивает подпись **побайтово в постоянном времени** (`timingSafeEqual`),
   а не оператором равенства — иначе время сравнения подсказывает атакующему,
   сколько символов он угадал.
3. Отклоняет пакет старше **24 часов**.

Подделать initData без токена бота нельзя. Токен известен только серверу.

Сессия ученика — свой JWT на 24 часа, ровно на срок свежести initData: жить
дольше, чем подтверждение личности, у неё нет причин.

### Почему два вида токенов, а не один

Токены персонала и учеников подписаны одним секретом, но несут разное поле
`kind`, и проверяются разными функциями. В запросе они лежат в разных
свойствах: `request.auth` и `request.studentAuth`.

Смысл — сделать невозможной ошибку «ученический токен случайно удовлетворил
маршрут персонала». Даже если разработчик перепутает вызов, тип не совпадёт и
проверка провалится. Это проверяется тестами: токен персонала на ученическом
маршруте даёт 401, и наоборот.

## Разграничение доступа

### Изоляция арендаторов

Каждый курс принадлежит преподавателю. Все маршруты, работающие с курсом,
проходят через одну функцию `loadAccessibleCourse`. Она:

- отказывает, если курс принадлежит другому преподавателю;
- для помощника дополнительно требует строку разрешения именно на этот курс.

**Отказ всегда `404`, а не `403`.** Разница принципиальна: `403` подтвердил бы,
что идентификатор существует у кого-то другого, и позволил бы перебором
составить карту чужих курсов. `404` не различает «нет такого» и «не ваш».

Модули, уроки, задания и сдачи поднимаются к своему курсу и проходят ту же
проверку — отдельной логики доступа у них нет.

### Права помощника

Три возможности, выдаются по курсам отдельно: проверять домашние работы,
управлять доступом, вести чёрный список. Помощник без нужного права получает
отказ, даже если курс ему открыт.

### Шлюз мини-аппа

Пока ученик не заполнил анкету, приложение закрыто целиком. Проверка стоит **в
плагине авторизации**, а не в маршрутах: открыт список из четырёх адресов,
ведущих к самой форме, всё остальное под `/api/v1/app/` отвечает `403`.

Новый маршрут закрыт по умолчанию. Это выбранное направление ошибки: забыть
добавить защиту невозможно, можно только забыть открыть нужное.

### Чёрный список закрывает возврат

Заблокированный ученик не получит контекст анкеты, не подаст её и не получит
приглашение в группу. Проверка стоит **и в API, и в боте**.

Это исправление реальной дыры, найденной при разборе кода: заблокированный
ученик мог пройти по старой ссылке курса и получить приглашение заново.

### Ключ экзамена

Ключ не отдаётся ученику ни в списке вариантов, ни в детали, ни после сдачи.
Баллы и правильность скрыты до проверки преподавателем: если возвращать
результат сразу, пересдачами вычисляется весь ключ. Это покрыто e2e-проверками.

### Фотографии работ

Фотография отдаётся не по прямой ссылке в Телеграм, а через API, и только
после проверки прав на конкретную сдачу. Идентификатор фотографии в Телеграме
наружу не выходит.

## Защита периметра

| Механизм | Значение | Зачем |
|---|---|---|
| Ограничение частоты, общее | 300 запросов в минуту | потолок против наводнения |
| Ограничение частоты, вход | 8 за 5 минут | против перебора пароля |
| CORS | список из четырёх адресов | два рабочих домена и два адреса разработки |
| Helmet | заголовки на ответах API | защита в глубину |
| HSTS, X-Frame-Options, nosniff | в Caddy на HTML | там, где важен кликджекинг |

Ограничение частоты считает **реальный адрес клиента** из `CF-Connecting-IP`,
который проставляет Cloudflare. Без этого все посетители за туннелем слились
бы в один адрес прокси, и один атакующий заблокировал бы вход всем сразу.

Запросы **без** этого заголовка от ограничения освобождены: прийти без него
можно только изнутри (локальная сеть, проверки здоровья, e2e-набор), потому
что порт API не опубликован наружу вовсе. Подделать заголовок снаружи, чтобы
обойти лимит, нельзя — снаружи путь только через Cloudflare.

Заголовка `Content-Security-Policy` на API нет намеренно: сервис отдаёт JSON и
двоичные данные, HTML не отдаёт никогда. CSP там ничего не охраняет, но ломает
выдачу фотографий. HTML отдаёт Caddy, и заголовки от кликджекинга стоят там.

Вебхук Телеграма проверяет секретный заголовок
`X-Telegram-Bot-Api-Secret-Token`. Без совпадения — `401`.

## Устойчивость к некорректному вводу

Все параметры маршрутов в API числовые. Нечисловой сегмент раньше доходил до
Postgres как `NaN` и возвращался ошибкой типа `bigint`, то есть `500` на
обычную опечатку в адресе. Теперь проверка стоит централизованно в хуке и
отвечает `404` — той же политики «не различаем неправильное и чужое».

Тела запросов проверяются схемами Zod. Ошибки Postgres переводятся в
осмысленные коды: нарушение внешнего ключа и уникальности становятся `409`, а
не безымянной пятисоткой.

Наружу никогда не уходит текст внутренней ошибки: клиент получает
`{"error":{"code":"internal_error"}}`, подробности идут в лог сервера.

## Персональные данные

**Что храним:** ФИО из анкеты, телефон ученика, телефон родителей, короткий
рассказ о себе, Telegram ID и имя профиля, фотографии домашних работ и
сертификатных решений (как идентификаторы файлов Телеграма).

**Телефон записывается только из контакта, которым ученик поделился о себе.**
Бот отклоняет чужой контакт: `contact.user_id` должен совпадать с
отправителем. Вручную ввести номер нельзя нигде.

**Дампы базы никогда не попадают в репозиторий.** Каталог `backups/` в
`.gitignore`, и это отмечено прямо в файле с указанием причины: там
персональные данные учеников.

**Витрина не показывает настоящих учеников.** Все макеты интерфейса на
`biolog.com.uz` собраны вёрсткой по образу реальных экранов. Скриншотов
рабочей панели там нет намеренно: на них были бы живые ФИО и телефоны
родителей.

**Демонстрации и съёмка.** Для показа платформы предполагается отдельный
демонстрационный набор данных, а не рабочая база.

## Секреты

Репозиторий **публичный**. Из этого следует всё остальное.

Секреты живут только в файлах `.env*`, которые исключены из Git широким
правилом: оно ловит и `.env.production`, и `.env.local`, и резервные копии
вида `.env.bak-20260826`. Наружу выходят только образцы `.env.example`.

Пароль базы не записан в `docker-compose.prod.yml`: файл коммитится, и в нём
стоит подстановка из переменной окружения с обязательным значением. Отсутствие
переменной останавливает запуск, а не поднимает базу с пустым паролем.

Что относится к секретам: `JWT_SECRET`, `TELEGRAM_BOT_TOKEN`,
`TELEGRAM_WEBHOOK_SECRET`, `CLOUDFLARE_TUNNEL_TOKEN`, `POSTGRES_PASSWORD`,
`TELEGRAM_API_ID` и `TELEGRAM_API_HASH`.

Токен бота — самый чувствительный из них: он же ключ проверки initData.
Утечка токена означает, что кто угодно может подделать вход любого ученика.

### Ключ, попавший в переписку

В ходе работы ключ стороннего API один раз оказался напечатан в выводе
команды. Правильная последовательность в таком случае:

1. **Отозвать ключ у поставщика.** Удаление строки из файла ничего не
   отзывает: утёкшее значение остаётся действующим.
2. Выпустить новый и положить его в `.env`.
3. Проверить, что старый перестал работать.

Проверять наличие ключа можно, показывать значение — нет. Команда проверки
должна отвечать «есть, длина такая-то», а не печатать содержимое.

## Что проверяется автоматически

Изоляция арендаторов и скрытие ключа — не декларации, а проверки в наборах
e2e, которые идут в CI на каждый коммит:

- чужой курс, модуль, урок, задание, сдача и вариант дают `404`;
- ученический токен на маршруте персонала и наоборот дают `401`;
- поддельная подпись initData даёт `401`, пакет без подписи — тоже;
- ученик без анкеты получает `403 not_onboarded` на всех закрытых маршрутах;
- ключ не появляется ни в списке вариантов, ни в детали;
- баллы скрыты до проверки преподавателем;
- чужой ученик не может прочитать и сдать чужую попытку.

Всего 256 проверок в трёх наборах. Подробности — в [11](11-эксплуатация.md).

Отдельно: скрипт, создающий учётные записи для тестов, защищён обязательной
переменной `E2E_SEED=yes`. Он заводит трёх пользователей с опубликованным
паролем, и опечатка в адресе базы не должна открыть три двери в рабочую
установку.

## Известные ограничения

**Нет второго фактора** для входа в панель. При текущем числе преподавателей
это принятый компромисс, а не упущение из виду.

**Нет журнала действий персонала** в отдельном виде. Дисциплинарные события
записываются с автором, но общего аудита «кто что открывал» нет.

**Нет автоматического удаления персональных данных** по истечении срока.
Удаление сейчас ручное.

**Секрет подписи один** на токены персонала и учеников. Разделение дало бы
возможность отзывать их независимо; сейчас смена секрета выкидывает всех.

**Резервные копии не шифруются** и лежат на той же машине. Копия за пределами
машины — следующий разумный шаг.
