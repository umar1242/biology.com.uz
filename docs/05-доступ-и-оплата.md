# 05. Доступ и оплата

## Как ученик попадает на курс

```
ссылка курса
   │
   ▼
бот просит номер телефона  ← подтверждает сам Телеграм, вручную не ввести
   │
   ▼
кнопка «Заполнить анкету» → мини-апп
   │
   ▼
анкета: ФИО, свой номер, номер родителей, пара слов о себе
   │
   ▼
ссылка на группу курса приходит сразу + начинается пробный период
```

Номер берётся только из контакта, которым ученик поделился о себе. Если
прислать чужой контакт, бот его отклонит: `contact.user_id` должен совпадать с
отправителем.

## Анкета как условие входа

Пока анкета не заполнена, мини-апп закрыт целиком. Проверка стоит не в каждом
маршруте, а в одном месте — плагине авторизации ученика. Открыты ровно четыре
адреса, ведущие к самой форме:

```
/api/v1/app/auth/telegram
/api/v1/app/application-target
/api/v1/app/courses/:id/application-context
/api/v1/app/courses/:id/application
```

Всё остальное под `/api/v1/app/` отвечает `403 not_onboarded`. Новый маршрут
закрыт по умолчанию — это безопасное направление ошибки.

## Пробный период

У курса есть число бесплатных уроков (по умолчанию 2). Отсчёт идёт **по
опубликованным урокам, а не по календарю**: ученик, записавшийся в паузе между
занятиями, не теряет пробный период просто так.

Считается строго: урок, опубликованный ровно в момент записи, в счёт не идёт.
Период считается исчерпанным, когда пройденных уроков стало больше бесплатных.

Логика вынесена в чистые функции `lessonsConsumedSince` и `isTrialExhausted` и
покрыта тестами на граничные случаи.

## Что происходит после пробного периода

Раз в час задача находит исчерпанные пробные доступы и **замораживает их**.

Заморозка означает ровно одно: приложение перестаёт пускать ученика. Он не
получит видео урока в чат, не сдаст домашнюю работу и не будет участвовать в
сертификатном экзамене. Из группы курса его **никто не удаляет**.

Это было отдельное продуктовое решение. Ученик может попросить отсрочку
оплаты, и преподаватель вправе его оставить. Автоматика не должна принимать
это решение за него.

В общий чат администраторов уходит уведомление с именем, курсом и числом
пройденных уроков.

## Отчисление

В панели есть раздел «Отчисление»: список замороженных учеников, которых ещё
не удаляли из группы, с ФИО, телефоном и телефоном родителей из анкеты.
Отметить нужных, нажать кнопку — бот удалит их из группы.

Удаление сделано как бан с немедленным разбаном: это выгон, а не вечная
блокировка, и ученика можно пригласить обратно, если доступ восстановят.

Отчёт возвращается по каждому ученику отдельно, а не одним успехом на всю
пачку: удаление может не пройти законно (бот не администратор, ученик уже
вышел), и преподаватель должен знать, кто именно не удалился.

На каждого ученика уходит отдельное уведомление в чат администраторов. Это
сделано намеренно: поиск по тегу `#student_12` должен показывать всю его
историю, а общий список не попал бы ни под один тег.

## Доступ вручную

Преподаватель выдаёт доступ в карточке ученика, указывая срок. При выдаче бот
отправляет ученику ссылку-приглашение в группу. Если приглашение отправить не
удалось, в чат администраторов приходит уведомление: ученик с доступом, но без
группы иначе не виден никому.

Доступ никогда не отзывается сам. За три дня до истечения приходит
предупреждение, после истечения — напоминания, пока преподаватель не примет
решение.

## Чёрный список

Попасть в него можно автоматически (по штрафным баллам) или вручную из
панели. В обоих случаях ученик удаляется из группы курса.

Чёрный список закрывает и повторную запись: заблокированный ученик не получит
ни контекст анкеты, ни возможность её подать, ни приглашение в группу.
Проверка стоит и в API, и в боте — обход по старой ссылке не работает.
